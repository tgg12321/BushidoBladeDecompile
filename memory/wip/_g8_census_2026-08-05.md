## Method

1. **Static screen** for the two hazards measured on `text1a`: (a) a **≤8-byte extern declared
   as a scalar, living outside GPREL16 range of `$gp`, with its address taken** — at `-G8` cc1
   thinks it is 1-insn addressable and stops CSE-ing the base, but maspsx cannot rewrite it, so
   we pay a `lui` per use; (b) a **file-scope `__asm__` block**, which floats to the top of
   `.text` because `-G8` defers function bodies.
2. **Build pass** on candidates: `make GP_FILES=<stem> build/src/<stem>.o`, compared to the
   oracle object with the normalized method. Changed functions split into **regress** (carries
   no rules today, so it is byte-perfect from pure C and any change must be re-matched — what
   the two `text1a` siblings were) and **payoff?** (carries rules, so a change is a candidate
   improvement).
3. **Payoff verification**: honest pure-C distance measured with the engine sandbox at `-G0`
   and `-G8` for every payoff candidate. "Closer" is measured, never inferred.

**Screen calibration.** Post-adoption `text1a` screens at **1 offender, asm=N** (it needed 3
honest-type fixes + 1 extraction, all now done; the 1 residual is harmless — the file builds to
oracle). So **offender count is an upper bound on fix cost, not a hard block**: `BLOCKED` reads
as "needs N honest-type fixes first". 12 of 30 files screened PASS but all are trivial
(0–4 functions, ≤1 rule-carrying); the substantive files all carry offenders.

### Two screen defects found (they change how the table above should be read)

1. **The `asm=` column only detects `__asm__(`, not `asm(`.** `code6cac_c_mid`
   is reported `asm=-` but carries a file-scope `asm(".section .rodata / .space 4 /
   .previous")` at `src/code6cac_c_mid.c:894`, and that block is what breaks its
   jump-table layout at `-G8`. A tree-wide re-scan (`tmp/csz/g8ad_asmscan.py`)
   confirms `code6cac_c_mid` is the ONLY file affected by this spelling gap.
2. **The offender screen requires `&SYM`, so plain scalar accesses are invisible.**
   An out-of-GPREL16-range `≤8`-byte extern that is merely *read/written* (never
   address-taken) also degrades: at `-G0` cc1 CSEs its address into a register,
   at `-G8` it emits a 1-insn small-data reference that maspsx cannot rewrite and
   `as` expands per use. This is the mechanism behind BOTH the "regress" and the
   "farther" outcomes, and the screen does not flag it.
3. **Object-level comparison is blind to function reordering.** `tools/objdiff.py`
   normalizes relocs, so a function whose bytes are unchanged but whose *position*
   moved is scored "same". For files with file-scope asm the `changed` column
   therefore understates the damage badly — see `main` below.

### `text1b` — diagnosed, fixed, and NOT worth adopting

The build failure is **not** `.set`/`.ent` desynchronisation and **not** the 73
flagged externs. Root cause, proven:

- maspsx tracks `current_func` **only from `.ent`** (`tools/maspsx/maspsx/__init__.py:946`),
  and `_sdata_allowed_for_current_func` (line 452) refuses the `%gp_rel` rewrite when
  `current_func` is not in `sdata_funcs.txt`.
- `text1b` has **65 whole-body canonical-asm functions written as file-scope
  `__asm__` string blocks**. At `-G0` they sit after a preceding `.ent`, so the
  rewrite fires by adjacency. At `-G8` cc1 defers all function bodies: measured,
  every one of the 65 `glabel` blocks lands at cc1 lines 164–11400 while the first
  `.ent` is at line **11472** — so `current_func` is `None` for all of them.
- One block (`func_8006BD28`) contains bare small-data refs: **5 loads + 2 stores**.
  The 2 stores need `$at`, inside the block's own `.set noat` → the hard error
  (`{standard input}:12258: Error: macro used $at after ".set noat"`).

**Fix built and verified byte-neutral**: `tmp/csz/t1b_extract.py` extracts all 65
blocks to `asm/funcs/<f>.s` + C stubs + `asmfix.txt replace_with_asmfile` entries
(63 splat files already existed; 2 generated). One scripted run; **full build SHA1
== oracle at `-G0`**. Removes 9,623 lines of inline asm from `src/text1b.c`.
Artifacts: `tmp/csz/t1b_extract_out/`.

**With the fix, `text1b` builds at `-G8`** — and the prize evaporates:
`changed=41, regress=39, payoff?=2`, and both payoff candidates measure **same**
(`InitFadePanel` 3→3, `func_8004DDB4` 476→476). 39 re-matches for zero gain.
**Do not adopt.** The extraction itself is independently worth landing as a
representation cleanup.

### `code6cac_c_mid` — recipe COMPLETE, zero regressions

`changed=2 / regress=0` — i.e. only the two payoff functions move.

1. **`D_800F33D8` is a 0x200-byte buffer, not a `u8`.** Evidence: `func_80038148`
