## Why every one-object spelling gives `lh v1,0(s7)` for the dot's [0] (dumps in v0/rtl, v1/rtl, vb/rtl)
1. An array element or struct field read goes through expr.c:4885 `change_address` -> explow.c:398
   `memory_address`, which calls `force_reg` on a constant address: `(set P (symbol_ref D_800A37E8))` (v1 .rtl insn 73).
   A scalar VAR_DECL keeps its shared DECL_RTL `(mem:HI (symbol_ref))`. cse.c:2656 `find_best_addr` never
   touches that, which is why the split scalars match.
2. `vec`'s `(set V sym)` (insn 25) is in the same CSE path: the dot block is block 1's fall-through, ";; Processing
   block from 2 to 180". cse_insn picks the cheapest member of sym's class: COST(pseudo V)=1 < sym=12 (cse.c:481,
   mips.h:2700). So P becomes V, and the read becomes `(mem/s:HI (reg/v 82))` (.cse:303).
3. [1]/[2] become `(plus V 2/4)` in cse1. cse2 folds them back to `const(sym+2/4)` (.cse2:333) because find_best_addr
   folds non-REG addresses. A bare-REG address is never folded: mips_address_cost(sym)=2 > REG 1 (mips.c:1632).
   V is allocated to s7, so reload does not substitute. Result: [1]/[2] match, [0] does not (score 2, 573/574 insns).
4. cc1psx on the same .i produces the same `lh $3,0($23)`. On the split-scalar .i it produces `lh $3,D_800A37E8`.
   So this is not a fork divergence.
Conclusion: the target needs either (a) the dot's [0] read to be a scalar-decl MEM, or (b) V's set to be outside
the dot's CSE path. (a) means two handles. (b) moves the `lui/addiu s7` out of block 1, but the target sets s7 at 0x804, before the bne.
