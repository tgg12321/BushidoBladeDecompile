maspsx: per-function COMMON gate (--comm-syms, maspsx_comm_syms.txt) + registration [infra-rule: maspsx-comm]

Builds the gate authorized by the owner ruling of 2026-09-26 (fourth batch, Q9;
.claude/rules/maspsx-gate-lists.md § "maspsx_comm_syms.txt", decisions.md "OWNER
RULING — maspsx COMMON gate"). Sony ASPSX 2.34 gives a COMMON (tentative-definition)
symbol gp addressing at its base only, never at sym+N; our C declares such
variables `extern`, so maspsx needs the storage class per function.

tools/maspsx/maspsx/__init__.py, maspsx.py
- `--comm-syms FILE` (`func: sym, sym`, the sdata_exclude.txt format) ->
  MaspsxProcessor(comm_sym_map=...). `_is_comm(symbol)` = upstream `.comm`
  knowledge OR listed for the current function (current_func comes from `.ent`,
  so INCLUDE_ASM bodies are never touched). The three existing
  `gp_allowed = gp_allow_offset or symbol not in comm_symbols` sites use it;
  they apply only to `sym+N` operands, so the gate only removes gp, only from
  sym+N (N != 0) of a listed symbol in a listed function; no storage is emitted,
  no instruction added/removed beyond maspsx's ordinary non-gp form (prong (b)).
- tests/test_comm_syms.py: listed offset non-gp / base gp / unlisted symbol
  keeps gp; inert for unlisted functions and without the list; the gate only
  turns gp lines into non-gp `sym+N` lines.
