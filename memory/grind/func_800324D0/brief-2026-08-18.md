## Static divergence hypothesis

The 27 is, in descending confidence:

1. **Register-allocation naming across a 5-pseudo leaf** — the walker (`$v1`), the byte (`$v0`), the
   command (`$a2`), the payload (`$a1`), plus the two hoisted invariants (`$t0`, `$a3`). The four pins
   exist precisely because the honest allocation disagrees. Family: **`register-alloc-pure-c`**
   (global.c `find_reg`, ascending order, priority `live_length × n_refs`; mips.h defines no
   `REG_ALLOC_ORDER`, so the scan is register-number ascending and caller-saves come first — which is
   why a frameless allocation is *reachable*, not a fluke). Secondary: **`compare-operand-order-register`**
   if the residual turns out to be a paired `$X ↔ $Y` swap around the `== 0xFF` / `< 0x80` tests.
2. **The elided `andi`** — a genuine 1-instruction delete plus whatever rename it drags. This is the
   *exact* mechanism resolved in `memory/reference/redundant-byte-andi-satan0main.md` (saTan0Main,
   commit `6dba050`): "GCC 2.7.2 tracks 'is this a byte' per register, globally. `$s2` is loaded by
   `lbu`, so GCC proves `$s2 <= 255` and deletes the redundant `& 0xFF`. To keep the andi, the masked
   value must be full-range." That memo's resolution was a **type-width** edit, and it is pure C.
3. **A redundant range check.** The C carries **both** `if (a2 < 12)` (`:2849`) and `switch (a2)`
   (`:2850`) over dense cases 0-11. Target has exactly **one** `sltiu $v0,$a2,0xC`. If GCC 2.7.2 does
   not fold the pair, that is an extra compare+branch (and possibly an extra label) in our stream.
4. **Frame risk** (see above) — if any pseudo takes `$s0+`, add ~6 instructions.

make `v0` a wide type (`s32`) that holds the stream byte, and derive the command as the explicitly
narrowed value the loop head consumes — i.e. move the truncation to the `a2 = v0` assignment rather

touching this, and note its warning that **cc1psx also elides the mask**, so this is never a compiler
question (`cc1psx-calibration-only`, `no-compiler-divergence`).
