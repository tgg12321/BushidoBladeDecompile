## What the target actually does — and why volatile was reached for

Frame `0x40`; saves at `0x30-0x3C`; outgoing args `0x0-0xC`; **locals occupy `0x10`, `0x18`, `0x20`,
`0x28` — an 8-byte stride, with `0x14/0x1C/0x24/0x2C` never touched.** Target round-trips those
slots through memory repeatedly:

```
asm:70   sw  $v0, 0x10($sp)      asm:94   sw  $v0, 0x10($sp)
asm:98   sw  $v0, 0x18($sp)      asm:99   lw  $a0, 0x10($sp)
asm:103  lw  $v0, 0x18($sp)      asm:104  sw  $a0, 0x10($sp)
asm:108  sw  $v0, 0x18($sp)      asm:114  lw  $v1, 0x18($sp)
asm:119  lw  $v1, 0x10($sp)      asm:124  lw  $v1, 0x18($sp)
asm:129  lw  $v1, 0x10($sp)      asm:133  lw  $a1, 0x18($sp)
```

That store/reload pattern is what the `volatile` was papering over. **No stack address is ever taken
in the target** (`grep` the asm: no `addiu $aN, $sp, …`), so it is not an escaped-address effect.

## Lever 1 (first, highest confidence) — declare the aggregate, drop the volatile

**GCC 2.7.2 keeps aggregate (struct/array) locals in memory unconditionally** — every field read is
an `lw`, every write an `sw`, with no `volatile` needed. That reproduces the whole round-trip
pattern honestly.

The 8-byte stride is corroborated by the *entity* layout this function walks: the fields it touches
come in 8-apart pairs — `arg0+0xF4`/`+0xFC`, `+0xD8`/`+0xE0`, `+0xB8`/`+0xC0`. So the four local
objects are almost certainly four instances of the same 8-byte record type the entity uses, with
only the first word read in this function (the untouched `0x14/0x1C/0x24/0x2C` words are that
record's second member — semantically real, **not** padding).

Rule file: `.claude/rules/split-scalars-hide-aggregate.md` (MoveImage, 2026-08-17) — "the scalars
are ONE array/struct splat never merged; declare the aggregate — NOT `const`". Prong (a) of the
`no-new-park-categories` per-word-merge sanction wants object-model evidence that predates the
byte-chasing session: the entity's own 8-apart field pairs are exactly that evidence. Check
`include/*.h` for an existing 8-byte pair type before inventing one.
