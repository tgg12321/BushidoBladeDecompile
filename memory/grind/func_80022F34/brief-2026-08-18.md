## 4. Delta to a COMPLETED-C commit

**The new family closes 0 of 11.** The 11 decompose (s1/s2, RTL-proven) as:

- **10 diffs** = the +8 phantom slot in *our* build (2× `sp` adjust, 4 saves, 4 restores at wrong
  offsets). Removing this needs a slot *subtracted*, which no declaration can do. Adding a
  `volatile u32 pad[2]` would make the frame 48 and the distance strictly worse.
- **1 diff** = the maspsx `.L`-label load-delay nop (`lhu v0,0(s2)` / `.L80022FD0:` / `sh v0,8(a0)`).
  This one **is** legitimately retirable, via the `[[maspsx-label-nop-gate]]` — add the function to
  `maspsx_label_nop_funcs.txt` and `retire` drops the `insert "nop" @ 36` rule. That is 1 of 11.

## 6. Judge-risk flags

1. **Mis-application risk is the top risk, and it runs the wrong way.** A session that reads the
   unpark list literally and reaches for a `volatile u32 pad[N]` here would be *increasing* an
   already-too-large frame. Any pad proposal for this function should be an automatic FAIL.
2. **Nothing supersedes the 2026-07-27 ruling.** That refusal turned on "no closing C construct
   exists at all", a ground the 2026-08-18 precedent does not touch. Presenting the unpark as if the
   ruling were overturned misstates the record.
3. **Partial-retire trap.** The maspsx nop *is* retirable (1 of 11) but retiring it alone does not
   reach a match and leaves the function mid-transition. Likewise, `candidate.c` (vH) makes the frame
   correct but would *invalidate the 10 frame-offset substs still in `regfix.txt`* — `evidence.md`
   [s1] warns explicitly: *"leaving vH + the stale substs would CORRUPT the oracle build."* Shipping
   vH without simultaneously retiring those 10 rules breaks the oracle.
4. **Re-grind cost with no new lever.** Six sessions, three modalities and ~48k permuter iterations
   are already banked as dead. Unparking without a new axis re-opens a measured plateau; the ledger's
   frontier explicitly says *"do NOT re-spin structural/permuter/forensic — all three measured dead."*
   The only stated re-attempt lever is a novel whole-function reshape (eliminate the switch-merge
   label / restructure the val1↔a0-reload dependency without reordering the chain).
