# Ruling 11 record — func_80029454 `rec`

Owner ruling 2026-09-26 Ruling 11 (.claude/rules/ordinary-c-judge-decidable.md), with the Q30
(FAKE-construct set-aside) and Q31 (mechanism + banked search) amendments. Raised by the layer-2
FAIL of 2026-09-29 (round 1): `rec` is written in both record loops, which both run, so it is a
reused local; Rulings 5 and 6 do not admit it (Ruling 6 (A): the loops are not exclusive).

## The variable and its values

`u8 *rec;` at function scope. Two write statements, each the address of record i of the
D_80101EC8 table (stride 0x44C):
- value 1: `rec = (u8 *)&D_80101EC8 + i * 0x44C;` at the top of the first record loop, read by
  that loop's field accesses (+0xE, +0x6A, +0x210.., +0x8C, +0x40, +0xA1..+0xA4, +0x286, +0xAD);
- value 2: the same statement in the second record loop, read by its field accesses (+0x210,
  +0x21C, +0x96, +0x92, +0xC, +0x8C, +0x234, +0x240).
No read can see both writes (the first loop's value is dead before the second loop's write), so
they are two values in Ruling 11's sense.

## (A)-(C), (E)-(H)

- (A) Local, not a parameter/global/static/register; declared once at function scope, the
  innermost scope enclosing both loops (both are top-level statements of the body); no `&rec`.
- (B) (1) each write is read in its own loop iteration (the field loads right after it);
  (2) no write re-stores a held value. The write is the first statement of every iteration of
  both loops, so: first loop i == 0 stores record 0 (rec uninitialized before); first loop
  i == 1 stores record 1 while rec holds record 0; entering the second loop rec always holds
  record 1, and its i == 0 write stores record 0; its i == 1 write stores record 1 while rec
  holds record 0. Every write differs from the held value on every feasible path.
- (C) (1)-(2) The one-variable-per-value spelling is `s/s0_blocklocal.c` below: identical
  statement list, only the declaration moves into each loop. (3) Both values are arithmetic
  (`lui/addiu` of D_80101EC8 + `addu` with the stride giv) present in the target at 0x8002950C
  and 0x8002988C.
- (E) (ii): both values are the same kind of quantity, a pointer to one D_80101EC8 record;
  `rec` is true of each write.
- (F) Annotation at the declaration in src/code6cac_b.c, citing this ruling and this file.
- (G) Layer-2 re-review of the exact body.
- (H) Everything else in the body is judged on its own (round-1 layer-2 passed the rest).

- Reuse body: one pseudo, reg 80, "used 70 times across 157 insns; dies in 3 places; crosses 8
  calls" (.flow). Both sets (insn 121 in the first loop, insn 615 in the second) are reg 80, and
  global allocation puts it in hard reg 17 ($s1) — the target's register for the record
  pointer in BOTH loops (0x80029514 `addu $s1,$s7,$v0`, 0x80029894 `addu $s1,$t3,$v0`).
- Split body: reg 100 (first loop, crosses 8 calls) -> $s1 as before; reg 265 (second loop)
  "used 18 times across 32 insns", crosses NO call -> hard reg 6 ($a2), and the second loop's
  whole register assignment shifts (83 raw lines, structdiff 6).

Mechanism: global.c find_reg (tools/gcc-2.7.2/global.c:970-975). An allocno whose
`allocno_calls_crossed` is 0 starts from `fixed_reg_set`, so the call-clobbered registers are
open to it, and reg_alloc_order offers them first; only an allocno that crosses a call is
restricted to `call_used_reg_set`'s complement (the callee-saved $s0-$s8).
`allocno_calls_crossed` is the sum of `reg_n_calls_crossed` over the allocno's pseudo
(global.c:449), which flow.c counts along the pseudo's live range. The second record loop
contains no call, so a pointer whose live range is only that loop crosses none and cannot be
seated in $s1; the target's $s1 in the second loop requires the second loop's record pointer to
be the same pseudo as the first loop's, whose range spans the first loop's eight calls
(func_800290B8 x2, func_80032854 x6).
