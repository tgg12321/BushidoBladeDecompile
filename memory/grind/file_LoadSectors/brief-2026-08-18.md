## 2. The refused-then-sanctioned spelling

Unlike the other two parks, the refused carrier **is already on main**, unannotated.
`src/ings.c:161-164`, verbatim:

```c
s32 file_LoadSectors(s32 a0, u8 *dest, s32 sector, s32 count) {
    s32 fd;
    s32 _pad[2];

```

Properties:

- **NOT volatile** — plain `s32 _pad[2]`. The family sanctions only the `volatile` spelling;
  `engine/volatile_cheats.py:_is_sanctioned_pad` requires the literal `volatile` token on the
  declaration line before it will stop treating the array as a cheat. **A respelling is
  mandatory**, and the 2026-08-18 func_8003CF84 prerequisite requires that respelling be
  oracle-verified.
- **Type/size:** `s32[2]` = 8 bytes. The ledger notes the size is recoverable only as a range
  (ALIGN8, 1–8 bytes), so a range annotation is appropriate per the SOTN `// n.b.!` convention.
- **Decl position:** **SECOND** declarator, between `fd` and `i` — i.e. *not* a leading pad.
  The SOTN exhibit and the two granted precedents (`pre_pad` in `func_8001E404`/`func_8003CF84`)
  are leading pads; the 2026-08-18 family text drops the position qualifier ("declared solely to
  reserve target's stack bytes"), so the middle position is inside the family as written but is a
  gratuitous deviation from every exhibit. Recommend moving it to first declarator when
  respelling — and re-verifying the oracle, since declaration order feeds `assign_stack_local`.
- **Genuinely unused:** never written, never read, never address-taken (confirmed by reading the
  whole body, `src/ings.c:161-183`). This is a true unused pad, **not** a barrier local — there
  is no `__asm__`, no `(void)&`, no volatile-qualified access anywhere in the function.
- **Earlier refusals of the same object:** `memory/grind/file_LoadSectors/evidence.md` banks
  *"WIP rejected_form: `_pad[2]` (DCE'd, pure dead-vars-local-aggregate) — adjudicator ruling

- **Frame forensics showing the target slot is genuinely untouched** — **PARTIALLY SATISFIED —
  the untouched-ness is proven, the partition is not.** Proven untouched

  > NOT vars=8. … The untouched sp+16..23 bytes are outgoing-args bytes. This dissolves the s0-era
  > 'original must have had an unused 8-byte local' proof."

## 6. Judge-risk flags

1. **The partition ambiguity is on the record in the function's own ledger.** A default-FAIL Judge
   reading `evidence.md` s1 will find the grind session's own conclusion that "vars = **0**" and
   the 8 bytes are args. The brief for acceptance has to argue explicitly that (i) the family's
   prerequisite is *untouched-ness*, not a frame-math proof, and (ii) the competing interpretation
   is now a named permanent refusal — not merely unsanctioned. Anything less reads as re-litigating
   the 2026-07-28 partition argument the owner already called insufficient.
2. **Producer 1 not measured.** Same gap as func_80017FA0, mitigated by 7 banked vars-axis probes;
   a cheap loop-guard probe would close it and is worth running before proposing.
3. **Position drift.** `_pad` sits second, not leading, unlike every exhibit and every prior grant.
   Low substantive risk, high optics risk with an adversarial reviewer; fix while respelling.
4. **The volatile respelling changes source that currently holds the oracle.** The function
   byte-matches *today*; a botched respelling (position move + volatile) can regress the oracle
   with no rules to fall back on. Oracle-verify the respelling in isolation before adding anything
   else, exactly as the 2026-08-18 func_8003CF84 prerequisite demands.
5. **Do not let the deleted-call candidate leak back in.** `memory/grind/file_LoadSectors/candidate.c`
   is the `if (0) { debug_printf(...) }` form and is *permanently refused*. A session that "applies
   candidate.c" mechanically ships a banned family.
