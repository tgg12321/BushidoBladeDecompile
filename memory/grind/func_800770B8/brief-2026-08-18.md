## The two mechanisms that matter

### 1. Loop-invariant hoist of a symbol address (4 rules, the only cluster adding instructions)

Target materialises `D_800A35D0` **inside** the loop — `lui v0,%hi` / `addiu v0,%lo` /
`addu v0,v1,v0` (T49-T51). Our honest build **hoists it out** into `t4` (`lui t4` / `addiu t4` at
H31-H32) and leaves only `addu v0,v1,t4` (H51). Cause: the C forms
`s16 *p_d0 = &(&D_800A35D0)[t0 * 2];` inside the loop and `loop.c`'s `move_movables` promotes the
single-set address pseudo.
Rules: `regfix.txt:2842` (`delete @ 30`, kills the hoisted `la $12`), `:2845/:2846` (two `insert` of
`lui`/`addiu` %hi/%lo — **inline-address injections**), `:2847` (`subst @ 49`).
Rule files: `defeat-licm-hoist-var-reuse`, `defeat-combine-symbol-fold`.

### 2. A value not available for the branch delay slot (3 rules; the entire 174-vs-175 shortfall)

Target T103-T104: `beqz v0,…` with **`addiu v0,a2,1`** in the delay slot — the per-player hit-count
increment computed speculatively before the branch resolves. We have no such instruction and compute
the increment inside the arm.
Rules: `regfix.txt:2888` `insert_after "addu $2,$6,1" @ 100` — a **genuine lost-codegen insert**

## Levers, in the dossier's order

1. **Kill the symbol-address hoist** (4 rules; the only inserts). Drop the `s16 *p_d0` intermediate
   and write the two zero stores as direct indexed accesses off the global, so no single-set
   loop-invariant pseudo exists for `move_movables`. If a direct indexed form still hoists, use the
   **proven `func_800858D0` shape**: route the address through a **multi-set** scratch local (a
   movable must be set exactly once in the loop). Read `memory/wip/func_800858D0/notes.md` first —
   same mechanism, already analysed to RTL level.
2. **Stage the hit counter so its increment is branch-independent** (3 rules; closes 174→175).
   Compute the incremented value into a named local *before* the `if` and assign it inside the arm,
   instead of `sp[t0] += 1;` in the arm. That is the `staged-value-reused-variable` shape and it is
   what puts `addiu v0,a2,1` in target's delay slot.
3. **Share one constant `1` across the two tail stores** (up to 6 rules). One local holding `1`, used
   for both `*((u8 *)(p + 0x67)) = 1;` and `D_800A35DC = …`, so GCC CSEs one `li` into `a1`. Do this
   together with removing the `asm("$16")` pin.
4. **Re-measure before touching the prologue interleave.** Prologue save order is downstream of how
   many pseudos survive to reload; the three changes above will move it.
