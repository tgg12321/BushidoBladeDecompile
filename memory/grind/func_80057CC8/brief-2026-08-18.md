## 6. Judge-risk flags

1. **The on-main starting point is a different species from the ledger baseline.** Main is
   neither candidate.c nor the s8 form: it is table-first-reassociated AND pinned. The grind
   session is not "deleting rules from a clean body" — it replaces the body wholesale. A
   Judge reading the diff sees the F3 construct arrive *together with* a pin removal and a
   reassociation; all three are needed for the 0, and only one of them is what the ruling
   sanctioned.
2. **A second, never-sanctioned lever rides along.** The `(offset + table)` vs
   `(table + offset)` reassociation is a codegen-motivated operand-order choice with no
   semantic content (it is what moved the floor 9→3). It was accepted as "pure C, no cheat"
   in `memory/wip/func_80057CC8/notes.md` (TL;DR) and never separately reviewed. Expect a
   question; it is defensible as ordinary expression spelling but it is not on the frozen
   list.
3. **`s16 new_var;` (`src/text1b.c:1876`, used `:1913`) — the biggest un-briefed risk.**
   Written once, never read; the source expression is already `s16` so the cast is a no-op;
   the name announces coercion-holder intent (cheat-reviewer test #6). The park reason never
   mentions it. Under a default-FAIL Judge reviewing the whole body for COMPLETED-C this is
   the most likely surprise FAIL. Test whether
   `*arg3 = cy + ((scale * (s32)*(&Judge + …)) >> 12);` is byte-identical and delete
   `new_var` if so. If it IS byte-load-bearing it needs its own justification — that would
   put it in the redundant-width-cast class the 2026-07-01 census explicitly declined to
   relax (`.claude/rules/no-new-park-categories.md:338-342`).
4. **The still-binding first judge_constraint.** state.json judge_constraints[0] bans "any
   shared-pointer split into two source-level locals … under any spelling". F3 does not relax
   it. Drifting from the inline form back toward `prev_p`/`next_p` locals FAILs on the old
   constraint, not the new family.
5. **Survey caveat that cuts both ways.** `tmp/sotn_family_surveys.md:243-246`: none of the
   SOTN F3 sites is annotated as match-motivated — they are *idiomatic style*, not
   *documented coercion*. The owner adopted the survey's reading that this favours sanction,
   but a Judge could read BB2's mandatory `/* FAKE */` annotation as an admission that BB2's
   use is coercion where SOTN's was style. The annotation is required regardless; word it as
   a family citation, not as a confession of purposelessness.
6. **Residual the family cannot close** — none expected (s8 measured 0/111), but if
   compilation-context drift moves the score off 0, F3 closes nothing and the function
   returns to a floor-3 endgame lock.
7. **Sandbox-invisible residue.** `sandbox --disable all` cannot see the `asm("s3")` pin, and
   per `memory/sandbox-lo16-text-addend-false-distance.md` it does not mask R_MIPS_LO16
   addends. A masked 0 is not a match; only `verify-oracle --rebuild` is.
