## Which ruling governs `work`
Not Ruling 5 (writes feed different consumers: cam->h10 store, the bisection compares, the
pitch0/pitch1 stores, math_SignExt12Div's argument), not 5-ext (writes not identical), not 6 (not
a record pointer), not 8 (vmNoiseOn only), not 9 (no BASE+K writes), not 10 (no public original
source). So Ruling 11, alone. `work` claims nothing else.

## Values (writes that can reach a common read)
- V1, per-fighter bisection angle: `work = base_pitch` (loop top), `work--` / `work++`,
  `work = cam->h10` (both bisection loops), `work = hi`. All reach `pitch1 = work` / `pitch0 = work`.
- V2, target angle: `work = (pitch0 < pitch1) ? pitch1 : pitch0`, `work = 0x80`, `work = 0x1C0`.

- V3, final step: `work = math_SignExt12Div(...)`, read by `cam->h10 += work`.

## (B) every write live; re-store records
(1) Every write statement's value is read on some path: loop-top write by `cam->h10 = work`;
`work--/++` by `hi = work + ...` / `lo = work - ...`; bisection `work = cam->h10` by the next
iteration's `d = (work - hi)` (i = 0 path) or `pitch1/0 = work` (clear arm); `work = hi` by
`pitch1/0 = work`; V2 writes by the clamps / the call argument; V3 by `cam->h10 += work`.
(2) Writes that can store a value `work` already holds on SOME feasible path, each with a feasible
path where it holds something else:
- `work = base_pitch` (loop top): on the p = 1 path work holds pitch0's result, which differs from
  base_pitch whenever the p = 0 bisection moved (e.g. blocked arm with D_800A30F0[0] == 0: work--).
- `work = cam->h10` (blocked loop): cam->h10 = hi + d/2 with d = wrap(work - hi); on a path with
  work - hi = 0x40 (d = 0x40) it stores hi + 0x20 = work - 0x20, not work.
- `work = hi`: on the path where the last test hit (work = cam->h10 = hi + d/2, d != 0) hi differs.
- `work = cam->h10` (clear loop): same as the blocked loop.
- `work = (pitch0 < pitch1) ? pitch1 : pitch0`: work holds pitch1 after the loop; on the path
  pitch0 > pitch1 it stores pitch0 != pitch1.
- clamps and V3: store 0x80 / 0x1C0 only when work is outside them; V3 is a new call result.

## (D) necessity by mechanism — two decisions, both needing ONE variable across V1, V2 and V3

M2 (V1+V2 in one pseudo), global.c find_reg. The target seats V2 (the max/clamp at
0x8001B09C-0x8001B0D8 and the `subu a0,s1,t2` argument) in $s1. In the reuse spelling the
single allocno for `work` is live across the loop's calls, so find_reg excludes every

-> $s1 (17). In EVERY per-value spelling V2's variable is live only from its first post-loop write
to the math_SignExt12Div argument, which is computed before the call, so it crosses no call; its

conflicts {2,29}, own_full_prefs {4}, pass1_used = 0..2,26..29,31 -> $a0 (4). That holds whatever
its declaration order, scope, type or statement order, because calls-crossed and the argument
preference come from V2's own reads and writes, which are fixed by the statement list. Ablations:
V2 split alone 23 (fin_G_split2), full per-value 25; ALLOCDBG dumps/allocdbg_final.txt vs
dumps/allocdbg_pv.txt (pv: tgt ord=10 hardreg=4 nrefs=8 livelen=11).

M1 (V1's variable referenced after base_pitch's last reference), cse.c make_regs_eqv
(tools/gcc-2.7.2/cse.c 844-857). The loop-top `work = base_pitch; cam->h10 = work;` makes

regno_last_uid is later than the head's. base_pitch's last reference is the final
`math_SignExt12Div(... - base_pitch)`. In the reuse spelling work is referenced after that

(dumps/insn703_final_cse.txt) -> target `lw s1,64(sp); sh s1,16(s6)`. In every per-value spelling

the store's source to base_pitch (dumps/insn703_fin_Gpv_scoped_rtl.txt -> _cse.txt: reg 315 ->
reg 92), which reload serves from base_pitch's spill slot (`lhu t2,64(sp); sh t2,16(s6)`). V3 split
alone: 15 (fin_G_split3), exactly those two instructions.

## `hi` / `lo` and the cancellation pair (not Ruling 11)
The bisection partner bound is two single-value locals, `hi` (blocked arm) and `lo` (clear arm).
A shared `other` also reaches 13 (bounds_fb_shared) but would need Ruling 11, whose (D)(3) fails
because a sanctioned-family split spelling reaches the target: `hi`/`lo` + `hi++; hi--;`
(candidate.c) = 13; `lo++; lo--;` instead = 13 (bounds_fb_cp_lo). Without the pair: 42
(bounds_fb_nopair), a pure $s0/$s1 swap of `work` and the bounds. Mechanism (global.c
allocno_compare, floor_log2(n_refs)*n_refs/live_length): without the pair `work` pri 13333 is
allocated before `hi` (11142) and `lo` (9428) and takes $s0 (dumps/allocdbg_bounds_nopair.txt);
the pair lifts `hi` to n_refs 21, pri 23333, so `hi` takes $s0 first and `lo` (no conflict with
hi) $s0, `work` $s1 (dumps/allocdbg_final.txt ord 9 / 11). combine folds the pair: 576/576.
Lever exhaustion: arm-scoped declarations 42 (bounds_fb_armscope), do{}while(0) around the
blocked bisection 74 (bounds_fb_dw_hi; both-arm wraps 111/85 in s2), duplicated `cam->h10 = hi + d/2`
into the d-fold arms 102 (bounds_fb_dup_hi; not re-merged), declaration order hi/lo vs lo/hi 70/70
(s2, older chassis), block-scoped hi/lo/i/d 62 (s2), permuter from clean base (s2b, N4, 2,310
iterations, no valid find; s3 per-value body, 7,851 iterations, no find). Family: semantically-null
