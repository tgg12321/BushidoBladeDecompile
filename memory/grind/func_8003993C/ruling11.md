## (D)(2) Mechanism
local-alloc (tools/gcc-2.7.2/local-alloc.c):
- `local_alloc` :470-478 gives a pseudo a local quantity (`reg_qty = -2`) only if it is used in
  ONE basic block (`reg_basic_block[i] >= 0`) and dies exactly once; otherwise `reg_qty = -1`
  and only global.c allocates it.
- `find_free_reg` :2135: for a quantity that crosses no call, `used` starts from
  `fixed_reg_set` (:2167) plus the registers live over its life, and the scan (:2251-2275, no
  REG_ALLOC_ORDER on MIPS) returns the LOWEST free register — a call-clobbered one ($v0..$t9)
  whenever one is free.
- `combine_regs` :1784: refuses a use-register that is not a local quantity (:1827) and a
  set-register with `reg_qty == -1` (:1836); otherwise (:1905-1922) ties the not-yet-allocated
  local set-register into the quantity of a local input that dies in this insn — the output then
  shares that input's hard register.
- `temp`: the target puts the selector in $s2 (0x80039D10), a callee-saved register, although the
  selector lives only in the straight-line else arm 0x80039D0C..0x80039D50 and crosses no call.
  In the reuse spelling pseudo 80 also carries the window (used in the event loop's blocks), so it
  is not local (no `in block` in its .lreg line); global.c allocates it (ord 15, $s2 = 18). In
  the per-value spelling `sel` (332) is `in block 21` with one death -> local; combine_regs ties
  it to the dying srl temp 337, find_free_reg returns $v0.
  (The window side follows from the same pseudo: 12 refs / 38 insns gives priority 9473 >
  `i`'s 8405, so the shared pseudo takes $s2 before `i` and `i` gets $s3 — the target's
  `addiu s3,s3,1` at 0x80039D8C. Alone, `window` has 6 refs / 35 insns = 3428 < 8405: `i` takes
  $s2 and `window` $s3 (v_pv.alloc). This is an allocator EFFECT, recorded for completeness; the
  necessity argument below rests on the selector alone.)
- `entry`: the target's if-arm sum `addu a0,v1,v0` (0x80039CF4) has an output register different
  from both inputs, which both die there. In the reuse spelling pseudo 163 is written in two
  blocks and dies in 2 places -> `reg_qty = -1` -> combine_regs refuses to tie it (:1836);
  global.c seats it in $a0 (ord 0, hardreg 4). In the per-value spelling `entry_a` (321) is `in
  block 20`, dies once -> local; at insn 652 input 327 (the D_80102764 load, local, REG_DEAD) is
  tried first and 321 is tied to it: `addu $3,$3,$2`.

## (D)(3) Necessity (every one-variable-per-value spelling)
**`temp`.** Property of the reuse spelling: the selector value is held by a pseudo that is not a
local-alloc quantity. In ANY one-variable-per-value spelling the selector has its own variable
V whose only writes are the selector computation and whose only reads are the selector's
consumers — in the straight-line else arm, which the target fixes as one basic block
(0x80039D0C..0x80039D50: no label, no branch; the (C)(2) statement list has none either). So V
is referenced in exactly one basic block and dies once, whatever its declaration order, scope,
integer type or name (a `volatile`/`static`/address-taken/global V lives in memory, which the
target's register-only arm rules out). By local-alloc.c :470-478 it is a local quantity; it
crosses no call, so find_free_reg's scan starts from the call-clobbered registers. The target's
whole else arm uses only $v0, $v1, $a0 and $at besides $s0-$s2, so over the selector's life at
most three of the sixteen call-clobbered registers ($v0-$v1, $a0-$a3, $t0-$t9) hold other values
of this block; find_free_reg returns one of the free ones, never $s2 (18). Therefore no per-value spelling produces `andi s2,v0,1`;
only a variable that also carries another (multi-block) value does, which is the reuse.
Constructs from sanctioned families cannot change this (next section).

**`entry`.** Property: the if-arm `entry` pseudo is not a local quantity. In ANY per-value
spelling `entry_a` is written by the one if-arm statement and read by the next; the target fixes
the if arm as straight-line code (0x80039CDC..0x80039D08), so `entry_a` is used in one block and
dies once -> local (:470-478). Both inputs of its sum are the D_80102764 load and `frame * 4`,
computed in the arm and dead after the sum (target: $v1 and $v0 are overwritten at
0x80039CF8/0x80039CFC with other values), so they are local and die at the sum. block_alloc calls
combine_regs(input, entry_a) and the tie succeeds for the first such input (:1905-1922; the
refusals at :1827/:1836 need a non-local register), so the output shares an input's hard
register — never the target's untied `addu a0,v1,v0`. Operand order cannot help (either input
ties). Only a variable written in more than one block is refused the tie (:1836): the reuse.

By mechanism:
- Dead stores never reach local-alloc: flow.c propagate_block (:1486-1493) turns a dead insn into
  NOTE_INSN_DELETED on the final pass before its registers are marked, and REG_BLOCK_GLOBAL is set
  only while marking surviving insns (:2075 sets, :2511 uses). Measured: `sel = 0` is in
  v_ext_sel_dead.rtl and .cse2 (`(set (reg/v:SI 163) (const_int 0))`) and gone in .flow; V's
  .lreg line keeps `in block N`. The self-assign, `V + 1 - 1` and `V - V` forms fold before RTL
  (V's reference count is unchanged in .lreg).
- A block boundary inside V's arm at zero bytes does not reach flow: jump.c :268-275 deletes
  every unreferenced label on each jump_optimize run and flow.c :354-360 starts blocks only at
  surviving labels and after jumps/barriers; do-while(0)'s labels and jumps are gone by flow
  (measured, both placements). A surviving label/jump in the arm is a branch the target lacks.
- A LIVE reference outside the arm is a read of V. It reads either (a) the value written in the
  arm, so V is live-in at the join block; the join is also entered from the other arm, so V is
  live back through that arm, the loop body and the latch — across 0x80039AC4..0x80039C64, where
  the target holds `i << 3` in $s2 (and, for `entry_a`, across the loop's calls, so global.c
  cannot seat it in call-clobbered $a0) — measured $s7 / spilled; or (b) no write at all (V read
  before its only write): an indeterminate value, undefined behavior in C90 (Annex G.2: "the
  value of an uninitialized object that has automatic storage duration is used before a value is
  assigned") — not ordinary C, and no sanctioned family admits it (the chain-extender entry is a
  detour of a LIVE, defined computation); measured anyway: $s4 / $s6, not the target. A read
  that sees an initializer is a second value in V, i.e. not a one-variable-per-value spelling.
- An address-taken V lives in memory; the target keeps both values in registers.
So no per-value spelling, with or without these constructs, reproduces `andi s2,v0,1` or
`addu a0,v1,v0`.
