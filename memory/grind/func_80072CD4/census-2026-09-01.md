# dup_if_else_arm full-population census — 2026-09-01

Precedent gate for **func_80072CD4** (owner ruling 2026-09-01, Ruling A).
Question: does SOTN master (US PSX build) contain at least one `dup_if_else_arm`
instance with the OPERATIVE PROPERTY — an unconditional common-TAIL statement
duplicated as the LAST statement of BOTH arms of an if/else (hoistable below the

**VERDICT: POSITIVE** — multiple manually-verified exhibits.

## Method

- Index: `docs/reference/sotn-construct-index.md` §`dup_if_else_arm` (lines 1661–2624).
- Pin: sotn-decomp commit `aa53500226ee84be763f3e8702b27de06456b3a7`; all file
  contents and splat configs read via `git show <pin>:<path>`.
- PSX scope set: parsed every `config/splat.us.*.yaml` at the pin (43 configs,
  all `platform: psx`), collected every `[addr, c, name]` segment resolved
  against the config's `src_path` → **1224 US-PSX .c files**.
- Screen: instead of trusting the index's single-line textual heuristic, ran a
  **full brace-aware scan of all 1224 PSX files** (`tmp/dup_screen.py`, raw
  output `tmp/dup_screen_out.json`): comments/strings stripped, PSP-only
  preprocessor regions (`VERSION_PSP`, `#if 0`) blanked, every `if (…) {…} else
  {…}` located, top-level statements of each arm extracted, LAST statements
  compared after whitespace normalization. This supersedes per-entry screening
  (catches multi-line duplications the index under-counts) while remaining
  anchored to the same population.
- Survivors manually verified by reading the pinned source.

self->step++;`). Textbook operative property, twice in one function.

## Verification scope note

What was verified: source-level operative property (identical statement,
top-level tail of BOTH arms, no arm-specific statements after it, unconditional,
semantically hoistable below the join), PSX-config membership at the pin, and
that each exhibit file is fully-matched C (no INCLUDE_ASM/INCLUDE_RODATA), i.e.
the shipped US-PSX bytes were produced from source carrying the duplication.
Whether GCC 2.7.2's cross_jump pass physically re-merged each pair in the
binary was not independently confirmed at the asm level; the exhibits compile
identical tail instruction sequences in both arms, the precondition for that
merge.

## Verdict

**POSITIVE.** The full 958-entry population (not the prior 40-entry sample)
plus a stronger full-file scan of all 1224 US-PSX build files yields 84
non-trivial identical-tail candidates, of which at least 8 instances across 4
files were manually confirmed to carry the exact operative property — including
`self->step++;` game code (rbo5/doors.c ×2), `D_801379BC++;` (dra/62DEC.c), a
US-branch `callback();` pair (dra/game_handlers.c), and five duplicated
`spucnt` store tails in matched Sony PsyQ library code (libspu/s_sca.c). This
flips func_80072CD4's precedent gate: writing an unconditional common tail
duplicated into both arms of an if/else is precedented in SOTN's matched US-PSX
source.
