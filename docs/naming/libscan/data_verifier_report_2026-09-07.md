## 3. Collisions, contradictions and notes for the rename tool

1. **`_spu_memList` is already a C macro** — `src/main.c:1981` `#define _spu_memList ((SpuMemRec *)g_spu_voice_key_c)` used by SpuMalloc. A blind rename of `g_spu_voice_key_c` -> `_spu_memList` produces `#define _spu_memList ((SpuMemRec *)_spu_memList)` (legal but self-referential and misleading). The tool must drop the macro and cast at the use sites (or rename the extern and delete the define). Sony's object is `SPU_MALLOC *_spu_memList` (a pointer); BB2 declares it `s32` — the cast sites stay.
2. **None of the "C-defined tables" are C-defined.** `SQRT` (D_8009C7A8), `rsin_tbl` (D_8009BF94), `rcossin_tbl` (D_8009C928), `GPU_printf` (D_8009BE70), `CD_debug` (D_800A11C0), `CD_status`/`CD_pos`/`CD_mode` (D_800A11C4/D0/D4) and the SKIP `_spu_rev_param` (D_800A2D94) are all `dlabel D_xxx` blocks in `asm/data/7D920.data.s`; the g_ names (g_gte_sqrt_table, g_sin_lut_q1, g_trig_sin_cos_table_packed, g_gpu_debug_func, g_cd_debug_level, g_cd_mode, g_cd_param, g_cd_ready_flag) are linker-script aliases in named_syms.txt/symbol_addrs.txt (bb2.map shows `g_x = 0x...` assignments beside the dlabel). Addresses confirmed in build/bb2.map. The rename must touch the dlabel/enddlabel in asm/data (or leave the D_ dlabel and re-point the alias) — an alias-only rename leaves two names for one object.
3. **`GPU_printf` is a data slot (function pointer), not a function** — Sony's `int (*GPU_printf)()`. gpu.h already types g_gpu_debug_func as `void (*)()`. Fine, but the name reads like a function; keep the extern's pointer type.
4. **Two aliases at Vcount (0x800A2634)**: g_sys_dma_region (5 refs in ings2.c, wrong meaning) AND g_irq_vsync_counter (0 refs, right meaning). Both must retire; the manifest lists both — good.
