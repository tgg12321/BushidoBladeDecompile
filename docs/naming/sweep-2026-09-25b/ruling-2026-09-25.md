# Owner ruling 2026-09-25: naming decision items from the 2026-09-25 sweeps

**Ruling (owner, in conversation, 2026-09-25):** asked for recommendations on the items the
2026-09-25 / 2026-09-25b naming sweeps held for an owner call, the owner answered **"Go ahead with
your recommendations"**. The false-positive directive ([[names-require-evidence]]) still governs:
a name lands only when its evidence meets an admitted class and a fresh default-refute verifier
has CONFIRMed the facts.

## 1. Verbatim Sony library code carries Sony's exact name, even over an accurate convention name

`_start` (0x800836EC) → `__SN_ENTRY_POINT`, the LIBSN SNMAIN XDEF at +0x0 (verbatim, single
placement; verify3-libsn). Extends the 2026-08-07 style ruling (bare Sony spelling for library
code) from "Sony name wearing a project prefix" to "accurate convention name" for code proven
byte-verbatim Sony. The old name stays findable in comments.

## 2. Approximate computations keep a plain name; the error bound goes in the evidence

`math_Distance3D` (0x80017748) and `math_Distance3D_16` (0x800177C8) are UPGRADED as they are
(computation-restatement), on the `math_Length3D` / `math_SquareRoot0` precedent: the recorded
evidence states the domain and error (≤0.9% for |d| ≥ 2^12; 0 below ≈426 / ≈1632; per-axis
domain < 2^17 / < 2^19). The proposed `_Shr2` / `_Shr4` suffixes are rejected — they read as
"distance >> 2". A name must not be false; it need not carry the error bound.

## 3. Sony static names that are not usable C globals are not applied

- `n` (LIBC2 RAND .bss, 0x800F1848): not applied — a one-letter global is ungreppable; the
  accurate `g_rand_state` stays.
- `rec` (LIBCOMB COMB .bss, 0x800F1AFC + members): not applied (185 locals/params named `rec`),
  but its **contradicted** aliases `g_spu_xfer_status_snapshot_plus_4` / `_plus_8` /
  `_plus_8_plus_4` (serial-link state, nothing SPU — the verified basis of the `sen` /
  `CombWaitCallback` rows) are RESET to their `D_` names.
- `p0.87` / `p1.88` (LIBGPU SYS, GCC function-scope statics): not applied — not C identifiers,
  and a spelling such as `p0_dot_87` would be our invention (same principle as the rejected
  suffixed `memclr`).

## 4. Evidence classes

- **Admitted — `sony-struct-restatement` (tier CORROBORATED):** a name may restate the fields a
  function writes/reads **only when** (a) the struct instance's identity is itself verified
  (e.g. CONFIRMed `g_gpu_db`), (b) the field layout comes from the Sony header (LIBGPU.H etc.),
  and (c) the EXE's own verified Sony code consumes those fields with that meaning (e.g.
  `SetDrawEnv` reads DRAWENV.isbg/r0/g0/b0 to emit the clear). No game semantics.
  First use: 0x80016768 → `gpu_SetDrawEnvBg`.
- **Admitted — computation-restatement extended to pair-private state:** the 2026-09-24 clause
  "a function that reads or writes game globals is NOT pure computation" does not bar a function
  whose only non-argument state is a global that a raw-EXE reference scan (incl. base-register,
  gp-relative, pointer-argument and data-word references) proves is touched by no code outside
  the named function pair, when the behaviour is proven by emulation. First use: `rng_SetSeed`,
  `rng_Next` (and their state word `g_rng_state`, 0x800A38BC), `scratchpad_Save`,
  `scratchpad_Restore`.
- **Not admitted — approximate normalization:** `gte_NormalizeIR` (0x800525D8) stays unnamed; its
  result is not left in IR (the name would be false regardless), ±32/4096 approximation, one caller.
