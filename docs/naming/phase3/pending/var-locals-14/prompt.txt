`tmp/codex/vl14_notes.md`, and put BOTH full contents in your final message (your worktree is discarded;
if the filesystem is read-only, the final message alone is fine).
Print the HEAD commit hash and cite file:line at it.

Rules: `.claude/rules/naming-bar.md` (N1-N6; "local / parameter: every use in its function bears it
out; a /* FAKE */ or no-purpose local keeps a neutral name"), `.claude/rules/completion-bar.md` item 3
("A no-purpose local may not wear a name that claims a purpose"). Names are snake_case C locals, short
and plain (`count`, `cursor_x`, `pad_pressed`), naming what the variable HOLDS at every use in
its function. Use the now-named globals, members, types and callee names as the main evidence.
Leave neutral (NO_NAME): any local whose declaration or use carries a FAKE comment, any local reused
for two different meanings in one function, register-shaping temps (`temp_*` whose only purpose is
codegen), and anything you can't show at every use. No numbers / flags / selector values in names.

Lessons from waves 1-7 (pending/var-locals{,-2..-7}/notes.txt): a pointer walking records is `*_cursor`; say the source (`slot_object`); an index says which array it indexes; counters vs indices (`files_checked`); no generic `buffer`; no name resting only on an unreviewed member name, another rename or a comment; say only what the code shows (`pad_buttons`, not `pad_pressed`); one consistent name per struct-typed param across functions; read-only copied pointer is `src_<things>`; an s32 only cast to a struct pointer is `<thing>_addr`; a -1/+1 only sign-tested is `x_direction`; with a separate forward prototype name only the definition. naming_keycheck refuses a name that appears in ANY #define body (grep them all).
Lessons from wave 8 (docs/naming/phase3/pending/var-locals-8/, landed): name what a computed angle points AT, not the struct's owner (`focus_bearing`, not `camera_bearing`); the output buffer of a decoder is `decoded_<thing>` (`decoded_motion_frame`), not `<thing>_values`; an output-only struct pointer param written once is `<thing>_out` (`pad_out`).
Lessons from wave 9 (docs/naming/phase3/pending/var-locals-9/, landed): name a coordinate by the axis its callers actually feed, not by the callee's own math spelling (callers pass world z, `y` is vertical: `*_z`); for a function symmetric in two argument groups, `first_*`/`second_*` (argument order) beat `segment_*`/`other_*` (`other` reads as the opponent); an index into `->vtx` is `vertex_index`, not `corner_index`. naming_keycheck counts comment text as tokens, so do not plan comment edits as part of the rename.
Lessons from wave 10: 'use audit not completed' is not a NO_NAME reason; audit every use. A local passed unchanged to an already-named callee param takes that name (`nav_set`).
Lessons from wave 11 (pending/var-locals-11/, landed): no `required_` when a sentinel (0xFF) means no requirement (`table_other_move_kind`); a value that only ever holds an upper bound is `*_max_distance`, not `*_radius`; a flag cleared when ANY input changes is `inputs_unchanged`, not `selection_unchanged`; a counter only used as the next ordinal written is `next_rank`, not `*_count`; `first_` when only column 0 of a pair gets a local.
Lessons from wave 12: a temp that only carries a value into another local stays neutral (`var_6`); `header` only at a record's start; header+blocks output is `output_addr`; name a shared boundary by the role true at every use (`first_section_end_offset`). SKIP K&R definitions (calc_LightMatrix): keycheck can't resolve them.
Lessons from wave 13 (landed 29/36): naming_keycheck REJECTS, so skip: an auto name declared twice in one function (even separate blocks); an OLD name found in any #define body in src/ or include/ (pad, bits, hi, x); an old name used as `name * name` (dy*dy). In 4510C.c `object` means a g_object_pool entry; a fighter record pointer is `fighter_record`/`*_fighter`.
