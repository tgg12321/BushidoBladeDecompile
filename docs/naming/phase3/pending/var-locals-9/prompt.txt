`tmp/codex/vl9_notes.md`, and put BOTH full contents in your final message (your worktree is discarded;

Print the HEAD commit hash and cite file:line at it.

Rules: `.claude/rules/naming-bar.md` (N1-N6; "local / parameter: every use in its function bears it
out; a /* FAKE */ or no-purpose local keeps a neutral name"), `.claude/rules/completion-bar.md` item 3
("A no-purpose local may not wear a name that claims a purpose"). Names are snake_case C locals, short
and plain (`count`, `cursor_x`, `pad_pressed`), naming what the variable HOLDS at every use in
its function. Use the now-named globals, members, types and callee names as the main evidence.
Leave neutral (NO_NAME): any local whose declaration or use carries a FAKE comment, any local reused
for two different meanings in one function, register-shaping temps (`temp_*` whose only purpose is
codegen), and anything you can't show at every use. No numbers / flags / selector values in names.

Lessons from waves 1-3 (pending/var-locals{,-2,-3}/, landed): a pointer walking many records is a
`*_cursor`, not the record name; say the source (`slot_object` from g_slot_objects[]); an index name
says which array it indexes; don't reuse a member name the function accesses; no name resting only on
an unreviewed member name; counters vs indices (`files_checked`); no generic `buffer` (`read_dest`,
`write_src`); a fixed array start vs its walking pointer get different names; `other_record` for
`p->other`, not `opponent`.
Lessons from wave 4 (docs/naming/phase3/pending/var-locals-4/, landed): say only what the code shows (`pad_buttons`, not `pad_pressed`, when pressed-vs-held rests only on a global's name); a param of a struct type used the same way across functions gets one consistent name (`draw_context` for every Unk8006EACCRec binding); a pointer only read from and copied elsewhere is `src_<things>`, with <things> shown by the consumer's computation, not by a comment.
Lessons from wave 5 (docs/naming/phase3/pending/var-locals-5/, landed): naming_keycheck refuses a destination name that appears anywhere in a #define body (any TU, any include), even if the macro is never expanded near the function (math_Popcount32 `bits` was dropped because a 9F9C.c bit-reader macro uses `bits`); grep every #define body for the proposed name. Mechanical names that claim no more than the code shows passed (`value_bits`, `divisor`, `scan_done`, `format_chunk` vs `format_cursor`).
Lessons from wave 6 (docs/naming/phase3/pending/var-locals-6/, landed): a name must rest on the code, not on another rename or a comment (`sheet_header` passed on the record's tp0/tp1/cells fields and the `.header` member typing, not on other functions' locals or a game.h comment); a list read only by sign and a terminator is `select_flags`, not `choices` or offsets; a cursor read in both passes of a function is not `copy_*`; a pointer that is both a CD-read destination and later read from is `file_buffer`, not `read_dest`.
Lessons from wave 7 (docs/naming/phase3/pending/var-locals-7/, landed): a -1/+1 value only tested `< 0` to pick ++ or -- is `x_direction`, not `x_step`; an s32 whose only use is a cast to a struct pointer is `<thing>_addr`, not the struct's name; a %s string chosen by a cursor test is `selected_prefix`, not `style` (nothing shows colour); a count bumped once per call of a named recorder may name that callee (`recorded_match_count`). When a function has a separate forward prototype, name only the definition's binding.
Lessons from wave 8 (docs/naming/phase3/pending/var-locals-8/, landed): name the thing a computed angle points AT from the code that defines it, not the struct's owner (`camera_bearing` failed: g_camera_default_view_record.unk_00 is the camera look-at point per camera_CalcEye, so `focus_bearing`); the output buffer of a decoder is `decoded_<thing>` (`decoded_motion_frame`), not `<thing>_values`; an output-only struct pointer param written once is `<thing>_out` (`pad_out`).
Freshness (`f:l=n`): `n` must not be another local/param in `f`, a file-scope identifier of that TU
(functions, globals, statics), an enum constant, a macro (grep include/ and the TU), a typedef/struct
tag, or a keyword. Each row names ONE binding in the unique definition of `f`; if one auto name (e.g.
`var_s0`) is declared twice in `f` (separate scopes), say which declaration (line) the row means.
