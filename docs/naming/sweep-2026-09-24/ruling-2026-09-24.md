# Owner ruling 2026-09-24: two new naming evidence classes admitted, verifier-gated

**Ruling (owner, in conversation, 2026-09-24):** during the 2026-09-24 naming sweep the owner
admitted two evidence classes that fall outside the previously admitted set (libscan-verbatim /
-xref / -near, in-binary-string, api-restatement). Asked plainly whether to apply rows of each
class that a fresh default-refute verifier had CONFIRMed, the owner answered **"Apply both"**.
The owner's false-positive directive (2026-08-07, [[owner-directives]]) still governs:
a row lands only on a CONFIRM verdict; PLAUSIBLE rows stay unapplied.

## 1. `computation-restatement` (census tier CORROBORATED)

The name restates ONLY the computation a small leaf (or near-leaf whose callees are VERIFIED)
function performs, **true for all inputs in the stated domain**, with zero game semantics.
Examples: `math_AlignUp4` = `(x+3)&~3`; `math_RotMatrixYXZ` = the Ry·Rx·Rz product built from
the sine table; `gpu_OffsetTexPolyFT4` = tpage/clut/v offsets applied to a POLY_FT4 at the
LIBGPU.H field offsets.

Admission requirements (what the 2026-09-24 rows met):
- The computation is derived from the function's own machine code, and the claimed formula is
  checked by **executing the function's instruction words from `disc/SLUS_006.63`** in an
  R3000A emulator that models branch- and load-delay slots, against the formula, over
  thousands of random + edge-case inputs with **0 mismatches**. Domain limits found by the
  emulation are recorded in the verifier note (e.g. `bitstream_ReadBits` valid for n=1..31).
- A name borrowing a Sony convention (e.g. the RotMatrix letter order = the matrix product
  order) must match that convention as the EXE's own Sony functions implement it —
  established by emulating those Sony functions, not by citing a reimplementation.
- A function that reads or writes game globals / game struct fields is NOT pure computation.

## 2. `libsn-pcdrv-protocol` (census tier CORROBORATED)

SN Systems PCdrv host-file calls (`PCopen`, `PCread`, `PCclose`, `PClseek`) identified by
their `break` trap code (0x103..0x107) and register marshalling, against two independently
fetched public references of the protocol (pcsx-redux/nugget `pcdrv.h`, DuckStation's host
handler) and the LIBSN.H prototypes. Where SN's own symbol for a routine is unknown the name is
a restatement (`pcdrv_ReadRaw` = the raw break-0x105 trap).
