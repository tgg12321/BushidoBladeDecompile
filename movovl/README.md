# MOVOVL.EXE sub-project — FMV/MDEC playback overlay

Parallel decomp scaffolding for `disc/STR/MOVOVL.EXE`, the boot-time FMV
overlay of Bushido Blade 2 (SLUS-00663). Entirely separate from the main-EXE
pipeline: nothing here touches `splat.yaml`, `bb2.ld`, `src/`, the Makefile,
or the engine. Build integration is future apply-time work — see
[docs/movovl/APPLY-PLAN.md](../docs/movovl/APPLY-PLAN.md).

## The binary (the oracle)

| Field | Value |
|---|---|
| File | `disc/STR/MOVOVL.EXE` (copy to `movovl/MOVOVL.EXE`; gitignored here) |
| SHA1 (whole file, the oracle) | `a1307dbebefca0b057e02509207d00f6225e13e4` |
| Size | 124,928 bytes = 0x800 PS-X EXE header + 122,880 (0x1E000) text image |

Also recorded in [`movovl.sha1`](movovl.sha1). Format notes:

## The game functions (independent census, 2026-08-07)

Census = prologues ∪ jal-targets over the non-library span (`j` targets
excluded — GCC 2.7.2 emits `j` for intra-function gotos). Reproduce with
`python3 movovl/tools/census_game_funcs.py`.

The libscan README says "11 functions + 3 stubs"; the honest census finds
**16 units = 11 prologue functions + 2 frameless leaf functions the scan's
prologue-counting missed (`func_801D9964`, `func_801D9D2C`) + 3 stubs**.
Same 3,832-byte total — the scan's byte claim holds exactly.

## Draft C status

All 16 functions have m2c first drafts in `src/draft/` (m2c
`--valid-syntax`, per `memory/reference/m2c-usage.md`; they need
`m2c_macros.h` for `M2C_UNK`/`M2C_FIELD`). **None are byte-verified — the
overlay has no build integration, so there is no compile/link/SHA1 loop
yet.** They are reading aids and starting points only.

## Policy for the 91% library portion

Mirror the main project's treatment of linked PsyQ library code: it is
**vendor code, kept as assembly** (the main EXE keeps PsyQ library functions
as asm / canonical-asm — they were never C compiled from our source, and the
libscan proves bit-verbatim identity with the SDK 3.5 `.LIB` archives; see
`docs/naming/movovl_scan/matches.json` for per-module evidence). Concretely:
the 59 `asm/lib*_*.s` files stay INCLUDE_ASM/linked-as-asm permanently; only
the 3,832 bytes of game code in `asm/game.s` are decomp targets. Do NOT grind
library modules to C — that would be re-deriving Sony's source, not
decompiling game code.
